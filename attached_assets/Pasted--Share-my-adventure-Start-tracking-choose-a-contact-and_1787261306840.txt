Connectivity shouldn't break the experience

This is where mapper.one's remote-use focus can make it better than generic location sharing.

The phone should continue recording GPS locally regardless of connectivity. When service is available:

GPS points → batch → mapper.one API → web viewer

When there's no service, the viewer sees:

Last update 18 minutes ago
Eric's last reported location was 4:17 PM. Their device may currently be outside cellular coverage.

Once the phone reconnects, it uploads the missing track points and the route fills in.

That's both technically practical and much more honest than pretending someone's location is "live" when it isn't.

Two-way messaging makes it considerably better

I'd absolutely include it, but keep v1 extremely lightweight.

Viewer:

"Running late?"

Mapper user receives:

Ann • 4:38 PM
Running late?

And they could have quick responses:

👍 I'm good
Running late
Heading back
Need help

Messages should also queue offline. The user gets them when connectivity returns.

You now have a lightweight communication channel specifically attached to an outdoor activity rather than trying to create another generic messaging app.

Then SOS becomes obvious

And an SMS can alert the contact to open the existing tracking page.

So you're not building two systems. You're building Live Adventure Sharing, with SOS layered onto it.

There's another feature I'd strongly consider: expected return

When sharing:

Share this activity

Contact: Ann

Expected duration:
2 hours

Notify if I'm overdue:
30 minutes

Then the viewer gets useful context:

Started: 3:15 PM
Expected back: ~5:15 PM
Last update: 4:52 PM

That solves a real outdoor problem. Someone at home doesn't necessarily need continuous notifications; they mostly want to know where you went and whether you're okay.

I'd avoid automatically declaring an emergency when someone is overdue. Instead, use language like "Eric's expected return time has passed" and let the contact decide what to do.

There's a nice viral loop here too

This feature naturally introduces mapper.one to other people.

Every mountain biker who shares a ride sends another person a mapper.one link.

The viewer sees:

Offline mapping and GPS tracking for wherever you go.

Get mapper.one

That could be a much better acquisition mechanism than asking existing users to explicitly invite friends.

That creates shareable activity pages in addition to your existing trail/route content.

I'd keep V1 surprisingly small

You don't need to build a Strava competitor. I'd launch with:

Start Tracking
Share Live Route
Select contact / send SMS link
Anonymous web viewer with map
Current/last-known location
Route traveled
Distance + elapsed time
"Last updated X minutes ago"
Simple viewer → user messages
End Activity

Then add expected-return alerts, SOS, multiple viewers, reactions/photos, and richer messaging afterward.

The underlying model can be very simple:

Activity → GPS Points → Share Token → Viewers → Messages
